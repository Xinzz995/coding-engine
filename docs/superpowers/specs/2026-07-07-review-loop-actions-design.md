# /review-loop 动作维度与裁决留痕设计

日期：2026-07-07
来源：validation gate 调研吸收轮 #1+#2（no-mistakes 的 finding action 三分法 auto-fix/ask-user/no-op 与 review-push 的 resolution 留痕 fixed/deferred/dismissed）；顺带兑现 ADR-007 后果节预告的 prd.tampered-* 人审包消费端

## 背景与动机

/review-loop 人审包的两个缺口：

1. **发现无动作分流**：发现清单只有缺陷类型 tag（bug:/scope:/…）与严重度排序，人审时无法一眼区分「可放心授权 agent 机械修」与「必须自己想清楚的产品判断」。no-mistakes 的核心原则「不要把产品判断伪装成代码修复」防的正是这个：scope: 私货被当 bug 顺手授权修掉，而正确动作可能是回改源 PRD 吸收它。
2. **裁决无留痕**：人审包只在对话输出，人审后 accept/defer/驳回的裁决随会话结束丢失——「产物必人审」教训的闭环缺后半段（审了什么、怎么裁决的、为什么，不可追溯）。

## 锁定决策

1. **动作维度（逐条标记）**：发现清单每条行尾追加 `→ <动作>`，格式 `<file>:<line> <tag> <缺陷>。<失败场景>。→ <动作>`。三档与机械判据：
   - **需人裁决**——满足任一：①挑战 story 意图或 AC 本身（行为不该存在/AC 可能写错）；②修复方案取决于产品语义选择（两种修法对应两种产品行为）；③删除性/破坏性变更（删功能、删数据、改公开接口）；④`scope:` 私货的去留（吸收进 PRD 还是删）。
   - **机械修**——修法唯一且不涉上述：bug 修复、边界补齐、测试补齐、质量族砍代码。
   - **仅提示**——信息性、无需动作、不阻塞（审查者拿不准是否算问题的归此档，预期低频）。
2. **动作与严重度正交**：排序规则不变（正确性族仍按严重度）；清单末总结行扩为 `审查结论：建议合并前处理 N 项正确性发现（其中 M 项需人裁决）`（N=0 时沿用现有空结果语）。裁决权仍全在人，动作标记只是人审分流建议——与「只读不改」哲学不冲突。
3. **留痕落盘**：人审包在对话输出（不变）之外落盘 `.workspace/review-YYYY-MM-DD.md`，同日已存在则 `-2`、`-3` 递增。文件含三层全文（+红旗区如有），发现清单每条带空槽 `- resolution: （待人审裁决）`。
4. **resolution 四态**：`[已修]`（detail 引用修复提交哈希）、`[接受]`（发现真实但不值得修，写理由）、`[推迟]`（后续处理，写去向）、`[驳回]`（审查者误报，写反证）。对照 review-push 的 fixed/deferred/dismissed，把 dismissed 拆为接受/驳回（发现真实但不修 vs 发现不成立），与项目 ledger 惯用语 accept/defer 对齐。
5. **裁决回填流程**：review-loop.md 新增「裁决回填」节——人审后人在对话给出裁决，执行者把每条 resolution 写回留痕文件；已修项在修复提交完成后回填哈希。修复动作本身仍由人另行授权（不变）。所有发现（含「仅提示」档——其 resolution 通常是 `[接受] 知悉`，人明确说不用逐条过时可批量回填）都必须有 resolution 后本轮审查才算闭环。
6. **prd.tampered 红旗区**：建立范围步骤新增检查 `.workspace/prd.tampered-*.json`；存在即在人审包顶部（层 1 之前）输出红旗区——文件清单 + 指引「diff 存档与 prd.json 看运行期被改了什么」；无篡改文件时整节省略不输出空节。兑现 ADR-007 后果节预告的消费端。
7. **硬性约束 1 修订**：改为「只读不改：不修改业务代码与文档、不写项目文件；唯一例外是留痕文件 `.workspace/review-*.md`（人审包落盘与裁决回填）——发现的问题列出来，修不修由人决定」。约束本意（不污染业务代码、不代人修）不变。
8. **归档连带**：prd-to-json 归档步骤的复制清单加 `review-*.md`（如存在）——否则下轮归档时留痕丢失或残留串轮。
9. **验证方式**：①grep 断言（动作三词、四态、红旗区、约束例外句的存在与位置，防示例自命中——断言限定条目位置而非全文计数）；②dogfood：对本仓库真实跑一次 /review-loop（可用 v0.17.0 轮 diff 做素材；.workspace 无 prd.json 时走既有降级规则，顺带验证降级模式下留痕文件同样生成）。

## 非目标

- **#10 词汇表单源不顺路**：本轮只动命令/skill 文档，不触引擎的 `[需求冲突]` 等字符串共享机制（引擎侧改动，另案）。
- JSON 结构化留痕 / HTML 报告——吸收轮 #3 的范围。
- compound-docs 消费留痕文件——裁决记录对沉淀有取证价值但 YAGNI，下次收口发现真实需要再加。
- 引擎与 dashboard 零改动。
- 不为留痕文件建独立子命令或自动化（回填是对话内顺手动作）。
