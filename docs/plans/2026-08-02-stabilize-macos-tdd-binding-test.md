# 稳定 macOS TDD 绑定复核回归

## 目标与边界

本计划只解决 Issue #119。它稳定
`src/workspace-safety/product-mutations.test.ts` 中「TDD 命令成功后重新核对全部绑定」这一条真实安全
回归，不修改生产超时、全局测试时限、工作区隔离或 Issue #91 的干净检出设计。

## 实测预算依据

同一 Git 文件树在 GitHub macOS runner 上的成功耗时为 3037、3440、2573、2284、2585、3971 和
2311ms，中位数 2585ms，最长成功样本 3971ms；另有一次超过 Vitest 默认 5000ms 后超时，原任务
重跑即通过。该场景串行执行三次真实受管进程检查，因此默认 5 秒预算与宿主抖动之间余量不足。

只为这一条测试设置 10000ms，约为最长成功样本的 2.5 倍。这个数字只限制测试本身，不改变生产
命令的任何超时；不提高全局时限，也不增加重试。

## 最小改动与可证伪完成合同

| 验收标准                        | 失败信号                              | 验证证据                                                                                 |
| ------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------- |
| TDD 命令仍真实改变有效 Git HEAD | 只改 mock、无有效新提交或 HEAD 未变化 | 预先用 `commit-tree` 建立相同树的子提交，受管命令用 `update-ref` 切换，并断言精确新 HEAD |
| HEAD 漂移后产品变更仍被拒绝     | 新 PRD 或 mutation domain 被安装      | 保留原有异常、旧 PRD、domain 不存在和 session 正常关闭断言                               |
| macOS 抖动不再触发默认 5 秒误报 | 连续目标回归仍超时                    | 本机目标测试连续至少 10 次通过；GitHub macOS 完整门禁复核                                |
| 改动不掩盖其他失败              | 全局时限增加、盲目重试或生产预算放宽  | 格式、静态检查、类型检查与全量测试全部通过                                               |

## 黄金原则对照

| 原则                 | 裁决                                                                   |
| -------------------- | ---------------------------------------------------------------------- |
| 先定义可证伪完成合同 | 适用；上表把安全语义、稳定性和全量回归分别绑定到断言与命令。           |
| 生成方不得自签       | 不改变任何产品验收或签发链路；以 Git 状态和工作区产物断言裁决测试。    |
| 自治扩大需同步防线   | 不适用；没有扩大写入、执行、合并、发布或删除权限。                     |
| 原生执行优先         | 适用；继续运行真实 Git 和现有受管进程，只把提交创建移出被测命令。      |
| 固化真实失败         | 适用；Issue #119 的 macOS 超时被固化为有局部预算且保留安全语义的回归。 |

远端完成证据仍需 Linux、macOS、Windows 的完整必需检查通过；本地通过不替代该平台证据。
