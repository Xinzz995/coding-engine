# 验收前提交漂移证据实施计划

## 目标与边界

本计划落实 GitHub Issue #107。现有引擎已经在项目检查、TDD 与 Validator 的关键边界重读
Git HEAD，并在身份变化或不可读时停止、撤销未验收候选且不增加重试。本轮只补齐持久诊断：
记录中止阶段、预期与实际提交身份，并保留已经执行的检查事实，同时明确其结果没有被采用。

本轮不改变停止、回滚、凭证撤销、重试、Final Review 或 GitHub 门禁语义；本地 workspace
证据也不被描述成共享交付证明。

## 可证伪完成合同

| 编号 | 完成条件 | 失败时可观察结果 | 验证证据 |
|---|---|---|---|
| AC-1 | 每次检查链因 HEAD 变化或不可读而停止时，iteration 都记录阶段、原因、预期 HEAD、实际 HEAD 与有界诊断 | 任何中止点只打印日志、原因误报或字段无界时失败 | 各边界竞态测试与 evidence 解析测试 |
| AC-2 | 项目检查或 TDD 已经结束后才发现漂移时，先保留真实命令结果，再用 `accepted=false` 标记未采用 | 已执行记录缺失，或仍显示普通通过/失败时失败 | 命令成功、失败、HEAD 不可读三类组合测试 |
| AC-3 | status 与 HTML report 明确区分“执行结果”和“裁决是否采用” | 未采用结果仍显示绿灯/普通红灯，或缺少具体中止原因时失败 | 文本、JSON 与 HTML 行级断言 |
| AC-4 | 异常后的第二次完整验收可以正常收敛，旧版缺省字段仍可读取 | 漂移永久污染后续轮次，或旧 evidence 被误拒绝时失败 | 两轮恢复测试与兼容解析测试 |

## 实施顺序

1. 扩展 evidence 判别联合和严格解析，新增通用 `validationHeadAbort`，并只允许检查记录以
   `accepted=false` 表示结果未采用；字段缺省维持旧记录语义。
2. 让所有提交身份中止点写入同一结构化原因；项目检查与 TDD 的执行事实必须先落盘，再停止。
3. status、JSON 与 report 展示最近中止原因，并把未采用结果从普通通过/失败中分离。
4. 更新架构与稳定约定，运行定向测试和完整项目检查。

## 黄金原则对照

| 原则 | 适用性与裁决 | 证据 |
|---|---|---|
| 1. 先定义可证伪完成合同 | 适用。AC-1 至 AC-4 明确成功、失败与验证方式。 | 解析、竞态、展示和恢复测试 |
| 2. 生成方不得自签 | 适用。命令返回值不决定是否采用；引擎重读 HEAD 后独立裁决。 | `accepted=false` 与中止记录 |
| 3. 自治扩大必须增加防线 | 本轮不扩大自治，只让已有停止行为可追溯；HEAD 不可读继续失败关闭。 | 不可读与变化两类回归 |
| 4. 原生执行优先、差异收口控制面 | 适用。沿用现有 Git 观察与统一 evidence/status/report，不增加 Runner 分支。 | 单一 schema 与跨入口展示 |
| 5. 以假绿与恢复衡量价值 | 适用。核心指标是未采用结果零假绿，且修复后能重新完整验收。 | 成功/失败命令漂移与第二轮收敛测试 |
