# Issue 207 外部链接核对自适应预算

## Context

干净验证检出会在受管 reader 中冻结允许产物目录里的普通文件链接。当前所有链接批次共用固定
30 秒期限；在冷缓存或高负载机器上，合法且受现有 1024 条链接、单文件 256 MiB、去重后 1 GiB
读取量限制的核对可能因此中断并迫使整轮重跑。

## Goals

- 由受管元数据核对建立链接数量与稳定去重目标的工作量，并使用
  `min(180000, 30000 + linkCount * 20 + ceil(distinctTargetBytes / 8388608) * 1000)`
  作为唯一内容核对预算。
- 从拓扑核对开始到内容读取和最终复核共用同一单调绝对期限；元数据预扫、内容读取和父进程监督
  均不得把计算出的期限缩短。
- 超时只给出有界的机械进度，不暴露链接或目标路径；身份、摘要、挂载、hard link 与回源拒绝仍然
  失败关闭。

## Non-Goals

- 不增加项目可调超时，不提高现有链接、单文件或总读取上限。
- 不修改 Windows 原生路径检查、Validator 语义、Agent 超时、自动合并或发布流程。
- 不用真实数分钟等待作为回归依据。

## Acceptance Criteria

以 `docs/prds/prd-issue-207.md` 的 US-001 为准。本计划只记录设计与验证对应关系，不替代该需求。

## Golden Principles

| 原则 | 适用性与设计裁决 | 验证证据 |
|---|---|---|
| 1. 可证伪完成合同 | 适用。公式、上限、重复目标、超时进度和身份变化都有明确可观察结果；无法建立或复核工作量一律拒绝。 | 确定性预算与受管 reader 测试、完整质量检查。 |
| 2. 生成方不得自签 | 适用。Builder 的 `passes=true` 只表示候选；实现仍由受管 reader、父进程监督、测试和后续 Validator 独立裁决。 | 结构化受管结果、测试、引擎的 Validator 流程。 |
| 3. 自治与可逆性对称 | 适用。只把受管读取的最长预算封顶为 180 秒，不新增写入、并行、合并或发布能力；中断、输出失败和未结算继续拒绝。 | 超时、中断和失败关闭回归；既有隔离检查。 |
| 4. 原生执行能力优先 | 适用。复用现有 Node 单调时钟、受管进程协调器和 reader，不增加运行依赖、服务或新的执行层。 | 类型检查、构建、受管 reader 回归。 |
| 5. 假绿与失败恢复优先 | 适用。将 RC5 的固定期限缺陷固化为受控时钟和慢 reader 回归，同时覆盖预算到期、目标替换、等长改写、回源与特殊/远程文件系统。 | 先红后绿的定向测试、完整测试与跨平台既有回归。 |

## Design

先由受管元数据 reader 对每条链接建立可复核身份和稳定去重目标大小；任何漂移、非法大小或冲突
都停止。随后从同一开始时刻按唯一公式计算绝对期限，内容 reader 在读取前后重新核对每条链接和
目标身份，并把每个稳定目标的摘要与身份绑定。父进程向每个受管 reader 传递同一剩余期限；所有
阶段都不能重新开始计时。

超时时由预算对象从机械计数器生成有界进度字段。尚不能可靠观察的值明确显示为不可得，不回显
reader 原始输出或任何路径。
