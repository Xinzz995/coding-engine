# Codex 启动诊断兼容修复

## 背景与边界

0.35.0 首个候选在 Go、Python Dogfood 的 Final Review 中稳定失败。当前 Codex CLI 会在
`thread.started` 与 `turn.started` 之间发送非致命的 `item.completed/error` 启动诊断；候选把它
归为未知工具事件。旧候选不得进入 staging。

本修复只适配有界、严格形状的启动诊断，不启用 Code Mode，不放宽命令、文件、MCP、Web 或
未知事件，不改变隔离声明的机械裁决。包版本保持 0.35.0；修复合并后重新生成候选并重跑三仓
Dogfood。

Python 受控复现还观察到 Codex 在同一 turn 内发送顶层网络重连通知，并在 WebSocket 重试耗尽
后发送 HTTPS 回退 item。官方生产端把这些通知保持为运行中状态，随后仍可返回唯一结果并完成
turn。审查调用忽略用户配置并使用内置 OpenAI provider 的固定五次重试边界，因此回退前必须能
观察到有序的 `2/5` 至 `5/5`；本轮不兼容任意自定义重试配置。

## 黄金原则对照

1. **可证伪合同**：上表逐条绑定正向、反向测试和三仓真实运行；任何一项失败都停止发布。
2. **独立证据**：不采信 Runner 自述；事件扫描、隔离声明、远端门禁和候选摘要分别由引擎或 CI
   机械验证。
3. **自治与可逆性**：不扩大工具权限；旧候选废弃，新候选在人工批准 staging 前始终可丢弃。
4. **复用原生能力**：适配 Codex 官方 JSONL 事件，不复制 Runner；供应商差异只留在 Codex
   adapter。
5. **假绿与恢复**：先固化真实失败和多组反例，再验证成功；目标是消除误拒绝，同时保持工具
   逃逸假绿为零。真实验收记录 Runner、结局与耗时。

## 非目标

- 不把所有 `error` item 视为普通消息。
- 不按 `terminal_reason` 或任意 `turn.failed` 文本猜测失败类型。
- 不预先接受当前受控 Codex 版本尚未生成的 `waiting for network` 形状。
- 不预先接受 WebSocket 以 HTTP 426 静默切换 HTTPS 后从 `1/5` 开始且没有回退提示的序列；在
  取得本项目受控调用的真实证据前保持拒绝。
- 不接受已经发出最终回复后又断流并重发回复的极端恢复序列；在能绑定回复标识前保持拒绝。
- 不增加新的工具、网络、文件或命令权限。
- 不解决 #166 的独立工具策略绑定重构；本次沿用规则版本联动使旧结果失效。
- 不复用 RC1 的 Final Review 结论，也不以重跑碰绿代替新候选验证。
