# Issue 320 外部链接核对自适应预算

## Context

干净验证检出会在受管 reader 中冻结允许产物目录里的普通文件链接。固定 30 秒期限会在冷缓存或
高负载机器上过早拒绝合法核对；已关闭的 Issue 207 候选又在 reader 返回后先检查期限，导致
输出或进程结算故障与期限同时发生时被误报成普通超时。

## Goals

- 由受管元数据核对建立链接数量与稳定去重目标的工作量，并只使用
  `min(180000, 30000 + linkCount * 20 + ceil(distinctTargetBytes / 8388608) * 1000)`
  计算生产预算。
- 在元数据预扫前记录唯一单调起点；内容 reader、最终链接复核、父进程监督以及随后相关的
  整树、挂载和 hard link 复核共用由该起点得到的同一绝对期限。
- 先保留中断、输出、异常退出、残留进程树与结算证明故障，只有明确监督超时或完整正常结果
  越过绝对期限时才报告预算超时。
- 超时只给出有界的机械进度，不暴露链接或目标路径；身份、摘要、挂载、hard link 与回源拒绝
  继续失败关闭。

## Non-Goals

- 不增加项目可调超时，不提高 1024 条链接、单文件 256 MiB 或去重读取量 1 GiB 上限。
- 不修改 Windows 原生路径检查、Validator 隔离、自动合并或发布流程。
- 不继承 Issue 207 的成功声明、凭证或远端结果，也不用真实等待数分钟作为回归依据。

## Acceptance Criteria

以 `docs/prds/prd-issue-320.md` 的 US-001 为准。本计划只记录设计与验证对应关系，不替代需求。

## Golden Principles

| 原则 | 适用性与设计裁决 | 验证证据 |
|---|---|---|
| 1. 可证伪完成合同 | 适用。固定公式、上限、重复目标、统一期限、进度字段和故障优先级都有明确通过与拒绝结果；无法建立或复核工作量一律拒绝。 | 公式边界、受管 metadata/content、期限覆盖和失败关闭测试。 |
| 2. 生成方不得自签 | 适用。Builder 的 `passes=true` 仍只是候选；受管结果、项目检查和后续 Validator 独立裁决当前 Story 与提交。 | 结构化受管结果、完整检查、Validator 复核。 |
| 3. 自治与可逆性对称 | 适用。只把合法读取的最长期限封顶为 180 秒，不新增写入、并行、合并或发布能力；中断、输出失败、未结算与残留进程继续拒绝。 | 故障优先级、超时、中断和进程收口回归。 |
| 4. 原生执行能力优先 | 适用。复用 Node 单调时钟、现有受管进程协调器、metadata/content reader 和整树复核，不增加依赖或执行层。 | 类型检查、构建和既有跨平台回归。 |
| 5. 假绿与失败恢复优先 | 适用。先复现旧候选在期限边缘误报故障的失败，再修复共享裁决路径；同时保留目标漂移、回源、特殊文件系统和 hard link 回归。 | 先红后绿定向用例、完整测试与质量契约检查。 |

## Design

受管 metadata reader 先对每条链接建立可复核身份和目标大小，按稳定目标身份去重并拒绝非法、
冲突或超限工作量。随后内容 reader 只读取各稳定目标的一条代表链接，最终 metadata reader 再
核对全部链接；三个阶段共享从预扫前起算的绝对期限。调用方保留同一预算对象，把期限继续传入
最终整树遍历，并在挂载与 hard link 复核前后检查。

reader 返回后先裁决中断、输出故障、异常退出、残留进程树和结算证明，再裁决监督超时；只有
完整且结构合法的正常输出才做绝对期限检查。超时诊断仅包含固定字段和数值或 `unavailable`。

## Rollback

如果身份、摘要、拓扑、监督或跨平台检查退化，回退本 Story 提交；不得以延长项目级超时、跳过
复核、重试后放行或热缓存成功来恢复绿色。
