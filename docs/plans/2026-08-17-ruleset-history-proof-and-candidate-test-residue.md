# Ruleset 历史补证与候选测试残留修复

## 问题与边界

0.37.0 重建候选在 PR #261 上完成 Story、机械门禁、审计版 Validator 与三轴 Shadow Review
后，GitHub Ruleset 详情省略了 `bypass_actors`。GitHub 官方合同允许调用者没有 Ruleset 写权限
时省略该字段；当前解析器把缺失直接判为非法，因此无法核验已经全部绿色的远端总闸。最新
Ruleset 历史版本仍提供完整 state，可在不扩大远端权限的前提下补证，但必须防止读取期间发生
版本竞态，不能把“字段缺失”直接解释成空数组。

同次实测还暴露两项测试残留：外部 `CODING_X_CODEX_BIN` 会污染默认参数测试；macOS 24 上
模型路由升级测试超过写死的 20 秒预算。两者都不代表产品行为失败，但会制造假红并拖慢候选闭环。

本计划由政策例外 Issue #262 跟踪。只修 Ruleset 读取证明和两项测试残留；不实现 Shadow
review-decision 候选身份支持、CI 快速通道、队列、轮询、发布或更多 Agent 编排。

## 可证伪完成合同

| # | 完成条件 | 通过证据 | 失败观察 |
| -: | --- | --- | --- |
| 1 | 详情直接返回 `bypass_actors` 时继续严格解析，不读取历史 | 普通/受管客户端调用序列测试 | 无条件增加历史读取或放宽现有形状 |
| 2 | 详情省略该字段时，只能由最新历史版本的完整 state 补证 | 当前真实响应形状回归；结果得到明确空列表 | 把缺失字段直接当成空列表 |
| 3 | 历史版本在读取前后变化、当前详情变化、历史 state 与当前详情任一核心字段不同或历史仍缺字段时失败关闭 | 版本竞态、规则/条件差异、缺字段测试全部拒绝 | 混用两个版本或旧历史状态签绿 |
| 4 | 普通 doctor/status 与受管 Final Review/candidate-proof 使用同一补证判据 | 两类客户端分别通过真实命令形状测试 | 一条路径能通过而另一条仍因同一响应失败 |
| 5 | 默认 Agent 参数测试不继承宿主 Runner 覆盖变量，覆盖变量行为仍由独立测试证明 | 注入 `CODING_X_CODEX_BIN` 后定向测试通过 | 默认测试继续依赖宿主环境，或覆盖能力被删掉 |
| 6 | 只校准已在 macOS 24 实证超时的模型路由单测预算，不修改产品超时 | 定向重复运行与完整测试通过 | 扩大运行时超时、吞掉未结算进程或整组测试无限放宽 |
| 7 | 修复后的候选重新完成 #250，不复用旧候选或旧 workspace | 新 main、新 candidate run、新 PR/workspace 与单次补签实证 | 用 32023372774 或 PR #261 的旧证明冒充修复后结果 |

## 设计裁决

1. Ruleset 当前详情含绕过列表时保持原路径。只有字段完全省略时才读取
   `rulesets/{id}/history?per_page=1`、对应最新版本 state，再次读取当前详情和最新历史标识。
2. 补证前后必须满足：最新版本 ID 不变、历史响应版本 ID 一致、当前详情 `updated_at` 不变，且
   历史 state 与当前详情的 id、name、target、enforcement、conditions、rules 完全相同。历史
   state 必须自己携带合法数组形式的 `bypass_actors`。
3. 比较使用解析后的结构化核心字段，不依赖 JSON 属性顺序；任一字段无法解析或不一致都抛出
   非重试的无效响应错误。网络与 5xx 仍沿用既有有界重试。
4. 同一纯验证函数供同步 `gh` 客户端和受监督异步客户端调用；两类客户端只负责按相同顺序取数。
5. Agent 默认参数测试显式传入空环境；环境覆盖的独立测试继续验证真实覆盖行为。
6. 只把发生超时的单测从 20 秒提升到 30 秒，并给所在串行分组留出 40 秒上限；产品的 Builder、
   Validator、门禁和进程结算时限不变。

## 黄金原则逐项对照

### 1. 先定义可证伪的完成合同

- **适用性**：适用；远端形状补证若边界模糊会直接制造假绿。
- **裁决**：以上七项分别绑定成功、竞态拒绝、双客户端一致和真实候选复验。
- **验证证据**：纯解析测试、同步/受管客户端测试、定向与全量门禁、全新候选 Dogfood。

### 2. 生成方不得给自己签发通过

- **适用性**：适用；缺失字段不能由调用方猜成空列表。
- **裁决**：绕过列表只能来自 GitHub 最新历史 state，并与当前详情及稳定版本标识机械对齐。
- **验证证据**：历史缺字段、字段差异和读取竞态均失败关闭。

### 3. 自治范围扩大时同步增加防线与可逆性

- **适用性**：不增加写权限、合并、发布或删除能力，只增加只读 API 调用。
- **裁决**：读取次数有界；原直接详情路径保留；回退只需移除历史补证函数。
- **验证证据**：调用序列测试证明直接路径不增加请求，补证路径固定且竞态拒绝。

### 4. 原生执行能力优先复用

- **适用性**：适用；GitHub 原生 Ruleset history 是当前状态的版本化来源。
- **裁决**：复用官方历史端点，不自建远端缓存或持久凭证库。
- **验证证据**：真实 API 响应与官方权限可见性合同对账。

### 5. 以假绿率和失败恢复衡量价值

- **适用性**：适用；目标同时消除一次远端假无效和两项测试假红。
- **裁决**：先固化三类真实失败，再验证成功路径；任何身份不一致仍保持不可验证。
- **指标**：候选远端读取从 invalid 恢复为真实 pending/ready；测试不再因宿主变量或已证实的调度
  余量假红；#250 最终记录补签耗时与此前整套重跑耗时。

## 验证顺序

1. 定向运行 Ruleset 解析、同步客户端、受管客户端、Agent 参数与模型路由测试。
2. 对模型路由目标用例连续运行，确认预算不是单次偶然通过。
3. 运行格式、lint、类型、构建、仓库健康、依赖审计和完整测试。
4. 通过受保护 PR 和 GitHub 七套矩阵后合并；从新 main 重建候选并重做 Issue #250。

## 当前验证证据

- 当前 GitHub 真实响应中，两个 Ruleset 详情均省略 `bypass_actors`；最新 history state 分别提供
  空列表。修复分支的在线 Shadow doctor 通过，交付状态恢复为 `ready`，约 38 秒完成全部远端读取。
- 同步/受管 GitHub 客户端、Agent 参数和模型路由相关完整回归为 4 个文件、93 项通过、1 项条件
  跳过；模型路由超时用例额外连续 10 轮通过。
- 格式、lint、类型、构建、仓库健康和依赖审计通过；完整测试 155 个文件通过、6 个跳过，
  2462 项通过、77 项跳过，耗时 1439.62 秒。
- 完整测试产生的 18 个可明确归属临时目录已逐一确认无打开句柄并移入废纸篓；系统临时区
  `coding-x-*` 顶层集合恢复到测试前相同的 4407 项与同一摘要。
