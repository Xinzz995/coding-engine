# 按变更范围执行必要检查并用定时全量检查发现漂移

## 背景与目标

0.37.0 候选实测再次暴露同一瓶颈：即使 PR 只改一份文档，Builder、本地引擎和 GitHub 多平台任务仍会
重复执行完整测试、构建和依赖审计。质量契约中的检查已经允许声明 `paths`，但本地门禁和生成的
GitHub workflow 都没有消费这些路径，因此当前配置只是说明文字，不会节省任何时间。

本轮目标是：PR 只运行当前净变更真正适用的检查；该 PR 在无绕过、要求最新默认分支的 Ruleset 下
通过后，合并不再触发第二次相同项目检查。每周及人工触发仍完整运行全部平台与全部检查，用独立巡检
发现运行环境、依赖、宿主镜像和缓存漂移。未知路径、差异无法证明或选择结果异常时必须自动回退全量，
不能用“快速路径”制造假绿。CodeQL 仍在 PR 和默认分支运行，维护默认分支的代码扫描事实。

本轮不做跨运行缓存、按历史成功跳过、自动轮询、队列、自动合并或自动发布。

## 可证伪完成合同

| # | 完成条件 | 通过证据 | 失败观察 |
| -: | --- | --- | --- |
| 1 | 引擎从固定 Story 起点到当前 HEAD 的 Git 变化摘要中机器计算命中的检查 ID | 文档路径只命中仓库健康；源码路径命中测试、构建和静态检查；改名按删除加新增处理 | Agent 自述“只改文档”即可跳过，或只看最后一次提交 |
| 2 | 没有 `paths` 的检查始终适用；有 `paths` 的检查只在任一路径命中时适用 | 单元测试覆盖混合、跨模块和多路径 | 一个匹配被后续不匹配覆盖，或无路径检查被误跳过 |
| 3 | 没有任何规则命中的未知改动、无法取得 Git 差异或选择结果不完整时回退本平台全量 | 未分类根文件、损坏摘要和缺失测试 seam 均执行全量 | 零检查被当作通过，或未知文件静默漏检 |
| 4 | 当前变更适用的检查全部通过后才生成复用证明，证明绑定 HEAD、基线、契约、平台、变化摘要和实际检查集合 | 任一绑定变化都拒绝复用；Validator 只能引用证明中明确执行的检查 | 文档子集证明被源码变更或完整测试 AC 复用 |

| 7 | 聚合总闸只允许“计划为不适用”的任务跳过；计划为适用的失败、取消、超时或跳过全部拒绝 | workflow 文本测试覆盖 success/skipped/failure 组合 | 依赖任务失败后聚合任务被连带跳过或误绿 |
| 8 | 每周计划任务与人工触发始终运行全部检查和全部平台，不读取变更选择 | 生成 workflow 含 schedule/workflow_dispatch；模拟事件全部任务为适用 | 定时任务也走文档快速路径，无法发现环境漂移 |
| 9 | coding-engine 自身的纯文档规则只保留仓库健康等必要检查，CodeQL 文档跳过不破坏当前 Ruleset | 真实文档 PR 上质量总闸、政策门禁与代码扫描保护均可判定 | 必需检查永久 Pending，或代码扫描被关闭/绕过 |
| 10 | 指标记录选择模式、执行清单、跳过清单和耗时，能与 #250 全量基线直接比较 | evidence、Validator 请求、最终 Review 和 Issue 评论可对账 | 只报“更快”而没有同类起止点与实际执行项 |

## 设计裁决

### 本地引擎

1. 继续以干净验证检出中的 `git diff-tree --no-renames` 作为变化真相源。Git helper 同时接收冻结质量契约
   中带 `paths` 的检查，用 Git 自己的 pathspec 语义返回命中的检查 ID；不让 Agent 提供分类结果，
   也不在 JavaScript 和 shell 中各写一套 glob 解释器。
2. 选择顺序固定为：当前平台不适用先跳过；无 `paths` 始终选择；有 `paths` 且命中才选择。若当前
   平台存在检查但最终零项，或 helper 结果缺项、重复、越界，则回退当前平台全部检查并记录
   `fallback-full`。
3. 变化摘要继续绑定完整原始 Git 清单；复用输入新增变化摘要和规范顺序的实际检查 ID。Validator 只
   能引用证明里执行过的机械能力，未执行能力仍必须按不可验证处理，不能因“文档改动”自由猜测。
4. 最终 Review 使用 PR base 到 head 的完整变化，不使用最后一个 Story 的局部范围。TDD 增加引用、
   默认分支变化、契约变化或选择集合变化仍使复用失效。

### GitHub 远端检查

1. 必需 `Quality Gate` workflow 不使用事件级 `paths`/`paths-ignore`，确保 `quality-gate` 总会报告；
   workflow 内先用固定版本 checkout 和 Git pathspec 生成只读执行计划。
2. 平台 job 只有在计划中至少一个 `checkId` 适用时才启动；job 内每个检查 step 再按计划执行。setup
   只在 job 启动后运行。聚合 job 使用 `always()`，并同时读取计划值与实际 job 结论。
3. Quality Gate 只由 `pull_request`、`schedule` 与 `workflow_dispatch` 触发。PR 使用 merge-base 到 head；
   对象缺失、非祖先、Git 命令异常或计划为空都选择 full。schedule 与 dispatch 直接生成 full 计划。
4. 默认分支不再触发 Quality Gate。该裁决依赖受管 Ruleset 同时满足：active、无绕过者、默认分支只能经
   PR、必需检查绑定 GitHub Actions 且要求最新默认分支；doctor 对任一漂移失败关闭。候选构建、staging
   和正式发布均运行自身的精确候选门禁，不读取默认分支 Quality Gate 作为发布凭证。PR workflow 默认
   检出 GitHub 生成的当前合并结果；base/head 变化会使旧结果失效。取消第二次事件不把任意历史绿色
   冒充 main 的新凭证。
5. CodeQL 保留每周全量扫描，并在每个 PR 和默认分支 push 运行。PR #270 已证明当前代码扫描 Ruleset
   不能接受文档 head 缺少分析，因此不以推测换时间，也不把项目检查与代码扫描混为一类。

### coding-engine 自身契约

- `tests`、`build`、`cli-smoke`、`dependency-audit` 等补齐它们真正受影响的代码、配置和依赖路径。
- `repository-health` 保留 `docs/**`、README、AGENTS、质量契约和 workflow 等治理路径。
- 未分类文件自动全量，因此补路径不是白名单安全边界；它只是已知改动的最小检查映射。
- 根 AGENTS 的提交前规则改为“通过当前改动适用的检查”；完整矩阵由每周巡检和发布候选继续承担。

## 黄金原则逐项对照

### 1. 先定义可证伪的完成合同

- **适用性**：适用；“文档改动很安全”本身不可验证。
- **裁决**：以上十项同时给出成功证据和失败观察；未知输入强制全量。
- **验证证据**：选择器、复用协议、workflow 文本、真实纯文档 PR 和定时全量运行共同验收。

### 2. 生成方不得给自己签发通过

- **适用性**：适用；Builder 能改文件，也能声称只改文档。
- **裁决**：范围由干净检出和 Git helper 计算；Agent 只看到结果，不能决定跳过项。
- **验证证据**：伪造 state、遗漏路径、最后提交障眼法和未知文件均不能得到快速通过。

### 3. 自治范围扩大时同步增加防线与可逆性

- **适用性**：本轮减少执行，不扩大写入、合并或发布权限，但会改变远端资源调度。
- **裁决**：任何 PR 选择不确定性回退全量；定时完整运行保留；默认分支无绕过且只能经过已通过必需
  检查的最新 PR。workflow 由契约生成，可通过回滚恢复默认分支触发。
- **验证证据**：失败关闭测试、Ruleset 回读、真实 PR/合并和人工 full dispatch。

### 4. 原生执行优先，差异只在控制平面

- **适用性**：适用。
- **原生能力对照**：变化范围和 pathspec 复用 Git；任务条件与 schedule 复用 GitHub Actions；不引入
  第三方路径过滤 action，也不自建测试缓存。
- **build/adapt 裁决**：coding-x 复用 GitHub 原生 PR 必需检查、Ruleset 与 schedule；只生成计划、绑定
  证据和聚合结论，项目命令仍来自质量契约，不建立跨运行缓存或自制合并凭证。
- **验证证据**：Node、Go、Python 契约生成测试保持语言无关。

### 5. 以假绿率和失败恢复衡量价值

- **适用性**：适用；优化不能只看节省分钟数。
- **裁决**：记录 scoped/fallback-full/full、执行项和耗时；每周 full 失败必须可见，快速路径异常自动恢复
  到 full。PR #271 合并后再次启动完整矩阵的真实重复必须固化为 workflow 触发回归。
- **验证证据**：先建立 #250 全量基线，再用纯文档真实 PR 对比总耗时；未知路径、环境漂移和合并后
  重复触发测试必须先红后绿。

## 实施与验收顺序

1. 扩展绑定变化摘要的检查选择结果，先补文档、源码、未知路径和改名失败回归。
2. 让本地门禁、Validator 证明和最终 Review 消费同一选择结果。
3. 扩展 workflow 生成器：计划任务、按项/按平台执行、聚合裁决、PR 触发、定时和人工 full；默认分支
   不再触发同一项目检查，CodeQL 默认分支触发保持独立。
4. 更新 coding-engine 契约、AGENTS、架构、发布手册、dogfood 回归与新 ADR。
5. 运行定向测试、格式、lint、typecheck、完整测试、build、repository-health 和依赖审计。
6. 通过受保护 PR 合并后，创建一个真实纯文档 PR，对账本地与远端执行清单、Ruleset、总耗时，并确认
   合并只触发 CodeQL、不再触发 Quality Gate。
7. 人工触发一次完整远端矩阵，确认定时 full 路径不是只存在于生成文本。

## 基线实证（优化前）

第五个 0.37.0 候选在 PR #267 的单文档 head `23570b0feb77548c1d96a75108836b0b26189992`
上完成了可对账基线：Builder 内完整测试耗时 1556.903 秒，引擎门禁内第二次完整测试耗时
1605.540 秒，仅两次测试合计 3162.443 秒（52 分 42 秒）；Builder 调用总耗时 1832029 ms，
引擎 gate 总耗时 1639318 ms。远端全部平台在 Final Review 完成前已经 ready，说明当前本地重复验证
反而比远端矩阵慢，无法形成原计划的“本地先完成、远端稍晚”窗口。

该 PR 的 Review 还正确发现原测试规格存在循环依赖：要求被测提交预先记录未来补签后的结果和耗时，
而事后补写会改变 head 并使原 Review/检查失效。PR 已关闭且未补签，证明文件和评论均为零。后续真实
验收必须把不可变夹具留在提交中，把运行结果写回 Issue/证明评论，不再要求提交预知未来状态。

纯文档 PR #270 随后证明项目检查快路有效：从 PR 创建到聚合总闸成功 40 秒，唯一项目命令
`repository-health` 运行 2 秒，其余代码命令与平台任务全部按计划跳过。但 active Ruleset 19747271
要求当前 PR 具有 CodeQL 分析；路径过滤使该 head 没有分析并保持合并阻断。因此按预先写明的回退
裁决恢复 CodeQL 每个 PR/main push 运行，不把治理必需检查误删为“文档不需要”。

恢复 CodeQL 的 PR #271 又暴露了第二个未闭环点：PR Quality Gate 从 2026-08-18 08:53:25Z 运行到
09:33:50Z，约 40 分 25 秒并全部通过；09:34:31Z 合并后，同一项目检查又在新 main 上立即启动。
当前 active Ruleset 19747271 已回读为无绕过者、强制 PR、必需检查要求最新默认分支；发布链也不读取
main 的 Quality Gate 作为候选凭证。因此这次合并后重跑只是重复成本，不是新的信任边界。本轮将它
固化为回归：项目 Quality Gate 只在 PR 裁决当前改动，环境漂移由每周/人工 full 发现；CodeQL 仍在
main 维护默认分支扫描结果。
