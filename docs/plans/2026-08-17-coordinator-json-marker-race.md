# 背景

PR #249 合并后的 main Quality Gate 运行 31963826960 在 Ubuntu Node 24 暴露真实偶发失败：
`coordinator.test.ts` 只等待控制文件路径出现，随后立即解析 JSON。测试子进程使用
`writeFileSync(..., { flag: 'wx' })` 时会先创建文件再写入内容，观察方可能在两步之间读到空文件，
得到 `Unexpected end of JSON input`。同一树在 PR 检查中通过，因此这是测试同步竞态，不是产品行为失败。

# 完成合同

| 验收标准                             | 失败时可观察结果                         | 验证方式                                                       |
| ------------------------------------ | ---------------------------------------- | -------------------------------------------------------------- |
| 预先存在的空标记不得被视为 ready     | JSON 解析立即抛错或把空内容当成完成      | 确定性回归先创建空文件，再补齐 JSON，读取方只返回完整记录      |
| POSIX 测试子进程只发布完整 JSON 标记 | 最终路径存在时仍可能读到半截内容         | 同目录临时文件完整写入后以排他硬链接原子发布；真实进程场景验证 |
| 原有超时与用户中断隔离语义不变       | verdict、隔离状态或清理结果改变          | 重复运行两个 opaque runner 场景并保留全部原断言                |
| 不改变生产行为                       | `src/workspace-safety` 生产文件发生差异  | Git diff 只包含测试、测试 fixture 与本计划                     |
| 仓库整体仍可信                       | 任一格式、静态、类型、测试或构建检查失败 | 完整本地门禁与 GitHub 多平台 Quality Gate                      |

# 黄金原则对照

1. **可证伪完成合同**：以上每项均绑定具体失败现象和验证方式。
2. **独立证据**：修复结论由确定性回归、真实子进程重复和 CI 裁决，不依赖实现者自述。
3. **自治与可逆性**：不扩大 Agent 权限、执行范围或自动合并能力；仅改变测试同步方式，不适用。
4. **原生能力优先**：直接复用文件系统同目录排他硬链接，不自建新的运行能力。
5. **真实失败固化**：运行 31963826960 的空 JSON 失败被转成稳定回归；目标指标是消除该类假红和重复重跑成本。
