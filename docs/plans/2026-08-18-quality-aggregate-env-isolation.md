# 质量总闸只读取声明的平台结果变量

## 问题与目标

候选运行 #32132089047 在全部产品测试通过到最后一项时失败。真实原因不是产品回归，而是生成的
Quality Gate 聚合脚本会枚举进程中所有 `EXPECTED_*` 环境变量；候选工作流恰好声明了
`EXPECTED_VERSION=0.37.0`，测试把它误当成平台预期结果，并因不存在对应结果而失败。

本轮让聚合脚本只读取质量契约声明的平台序号。环境中同名前缀的其他变量必须被忽略；契约内平台的
缺失、非法、失败、取消、超时或错误跳过仍必须失败关闭。失败候选作废，修复合并后从新 main 重建，
不得重跑旧候选并把它解释成包含修复。

## 可证伪完成合同

| # | 完成条件 | 通过证据 | 失败观察 |
| -: | --- | --- | --- |
| 1 | 聚合脚本只遍历质量契约生成的明确平台序号 | 生成文本包含固定序号列表，不再枚举环境变量名前缀 | 任意 `EXPECTED_*` 都进入裁决 |
| 2 | `EXPECTED_VERSION`、未知 `EXPECTED_*` 和 `RESULT_*` 不影响合法平台结果 | 回归测试带入候选工作流同名变量仍成功 | 候选环境再次制造假红 |
| 3 | 契约内任一平台预期值非法，或实际结果与预期不符，仍失败关闭 | 既有 skipped/failure/plan failure 反测继续失败 | 为消除污染而放宽真实平台裁决 |
| 4 | 生成器、仓库实际 workflow 和文档保持一致 | 仓库健康、定向测试与完整测试 | 只修测试夹具，实际工作流仍有同类隐患 |

## 黄金原则逐项对照

### 1. 先定义可证伪的完成合同

- **适用性**：适用；“候选重跑会通过”不能代替确定性边界。
- **裁决**：以上四项分别约束允许输入、忽略输入、失败路径和生成一致性。
- **验证证据**：候选真实失败回归、生成文本断言、仓库健康与新候选运行。

### 2. 生成方不得给自己签发通过

- **适用性**：适用；聚合总闸是机械裁判。
- **裁决**：允许读取的变量名由冻结质量契约生成，项目或 Agent 新增的环境变量不能加入裁决集合。
- **验证证据**：未知前缀变量被忽略，契约内失败结果仍被拒绝。

### 3. 自治范围扩大时同步增加防线与可逆性

- **适用性**：不扩大写入、合并、发布或执行权限，只收窄聚合脚本的输入集合。
- **裁决**：保留现有人工批准、受保护 PR 和失败候选作废边界；普通回退 PR 可恢复旧实现。
- **验证证据**：Policy Guard、完整远端矩阵和新候选三平台安装。

### 4. 原生执行优先，差异只在控制平面

- **适用性**：适用。
- **原生能力对照**：继续使用 GitHub 明确注入的 job 结果；不增加缓存、外部 action 或自制状态存储。
- **build/adapt 裁决**：生成时固定平台序号，项目命令和语言无关合同不变。
- **验证证据**：Node、Go、Python workflow 生成回归继续通过。

### 5. 以假绿率和失败恢复衡量价值

- **适用性**：适用；这是候选 #32132089047 的真实假红。
- **裁决**：先用 `EXPECTED_VERSION` 复现失败，再修正；不删除契约内非法值和失败结果反测。
- **验证证据**：定向测试先红后绿，完整检查通过后重建全新候选。

## 实施顺序

1. 在聚合测试环境加入候选工作流的 `EXPECTED_VERSION`，确认旧脚本失败。
2. 生成脚本改为只遍历契约声明的平台序号，并同步仓库 workflow。
3. 运行定向测试、格式、lint、typecheck、构建、完整测试、成品启动和仓库健康。
4. 通过受保护 PR 合并后，从新 main 重建候选并继续 Issue #250；旧失败运行只保留诊断证据。
