# 正式 Review GitHub 只读瞬时故障重试

## 背景与事实边界

0.34.0 coding-engine Dogfood 的三轴 Review 已进入执行流程，但在结果落盘前的
`远端核验后` authority snapshot 中，`gh repo view` 返回一次
`Post "https://api.github.com/graphql": EOF`。本轮按失败关闭规则退出 5，未生成
`final-review.json`，因此不能把未持久化的三轴结果称作通过。

普通 GitHub 只读客户端已经把 GraphQL EOF、连接重置及 408/500/502/503/504 归类为
瞬时故障，并最多尝试三次；正式 Review 的 authority snapshot 与 managed observation
没有复用这条规则，仍是单次读取。一次低概率断线会被一轮 Review 中的多次当前性核验放大。

本计划只重试幂等、受管、只读的 GitHub 观察。Git、Runner、文件、协议、权限、限流、
身份漂移、工作树变化、超时、中断、进程残留和临时域清理失败继续一次即阻断。

## 完成合同

| 验收标准             | 通过证据                                                                         | 失败观察                                       |
| -------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------- |
| 瞬时读取可恢复       | 首次 GraphQL EOF 或 HTTP 502 后，第二次完整读取成功                              | 一次 EOF 直接作废整轮 Review                   |
| 重试有界且可解释     | 最多三次，退避 250/500ms；耗尽错误包含尝试次数和最后原因                         | 无界重试，或耗尽后不显示次数与最后原因         |
| authority 证据不降级 | 每次重新执行完整快照，使用新临时域、nonce 和请求摘要；成功快照仍精确 14 个子进程 | 采用失败快照的前半段，或把子进程预算改成浮动值 |
| 只读受管边界不变     | 每次尝试都由 coordinator 证明自然结算、无后代残留和无 workspace 改动             | 绕回普通非受管客户端或缓存旧结果               |
| 永久错误不重试       | 401/403/404/422/429、坏 JSON、缺少工具、Git/Runner/协议错误都只执行一次          | 权限或数据错误被反复调用                       |
| 中断与异常仍失败关闭 | timeout、cancel、process-tree residue、临时域清理失败不重试且不落盘              | 异常被当作网络抖动放过                         |
| 模型不重复调用       | authority snapshot 的一次瞬时失败只增加机械快照次数，三轴调用次数不变            | 因机械重试重新调用模型                         |
| 发布身份重新建立     | 修复合并后作废旧候选，重建候选并重新完成三仓 Dogfood                             | 继续使用旧候选摘要或旧 Review 结果             |

## 设计裁决

1. authority snapshot 在外层重试整批快照，不在内嵌 helper 中重试单个 `gh` 子命令。
   每次失败快照完整丢弃并清理；成功尝试仍满足固定 14 子进程预算。
2. 只有自然结算、无 timeout、无外部终止、无后代残留、临时域成功删除，且失败步骤是固定
   `github-*` 读取时，才交给统一 GitHub 错误分类器判断是否可重试。
3. managed observation 只对 `gh` 的自然非零只读结果应用相同分类和三次上限；`git` 不重试。
4. 重试不使用缓存、不切换模型、不复用半份快照。下一次完整观察若发现 HEAD、base、PR、
   Story、规则、裁决或工作树变化，仍按现有当前性规则阻断。
5. 瞬时故障在限次内恢复时属于内部执行细节：不写入 Final Review 或交付凭证，也不为一次
   已恢复的网络抖动制造用户噪声；只有耗尽时才显示总次数和最后原因。
6. 现有 0.34.0 R6 候选绑定旧 `main` 和旧摘要。修复改变裁判实现后，必须废弃 R6，使用新
   `main` 重建候选并重新完成 coding-engine、Go、Python Dogfood。

## 黄金原则逐项对照

### 1. 先定义可证伪的完成合同

- **适用性**：适用。上表为每项行为同时给出成功证据与失败观察。
- **验证**：瞬时/永久错误矩阵、真实受管操作、Final Review 集成、全平台 CI 与三仓 Dogfood。

### 2. 生成方不得给自己签发通过

- **适用性**：适用。重试只重新取得机械观察，不改变 Validator、Reviewer 或 GitHub 的签发边界。
- **验证**：未取得一次完整成功快照时不生成 Final Review；候选继续只能产生 shadow 结论。

### 3. 自治范围扩大时同步增加防线与可逆性

- **适用性**：适用。系统将自动多发最多两次只读请求。
- **裁决**：只允许统一分类器确认的瞬时读取；固定次数、固定退避、终止信号优先；回退本 PR
  即恢复旧行为。

### 4. 原生执行优先，差异只在控制平面

- **适用性**：适用。仍调用项目外可信 `gh`，不引入代理服务、缓存或平台专用后门。
- **验证**：Linux、macOS、Windows 继续使用同一控制逻辑和原生 GitHub CLI。

### 5. 以假绿率和失败恢复衡量价值

- **适用性**：适用。本轮来自真实 Dogfood 的一次瞬时 EOF。
- **裁决**：目标只减少假红和整轮重做，不减少任何当前性核验；永久错误与不确定状态仍失败关闭。

## 实施顺序

1. 加入 authority snapshot 与 managed observation 的瞬时/永久错误回归。
2. 实现整批 authority retry 和受管 `gh` read retry。
3. 验证重试不增加模型调用、不放宽子进程预算、不留下临时域。
4. 运行格式、静态检查、类型检查、全量测试、构建和独立审查。
5. 合并后废弃 R6，重建候选并重新完成三仓 Dogfood。
