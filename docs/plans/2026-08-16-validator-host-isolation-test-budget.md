# Validator 主机隔离集成测试预算计划

## 背景与事实

PR #243 的 Quality Gate 运行 31927004519 在 macOS Node 22 与 24 同时出现两条 5000ms 测试超时：

- `keeps the candidate, issues no receipt and exits 5 when the profile boundary cannot be proven`
- `refuses a wrapper command as unobservable instead of sealing a partial invocation`

两条用例都通过 `runLoop()` 真实执行 Builder、Git、受管进程与失败证据落盘，但所在 describe 使用
Vitest 默认 5 秒上限；测试夹具里的 Builder/Validator 命令预算本身也是 5 秒。外层测试因此可能在
内部链路仍合法运行时先行终止。同一生产与测试代码在上一轮 31925573762 的两种 macOS 均通过；
当前提交只增加完成文档，两种 macOS 却同时在相同两条用例、相同 5000ms 边界失败，排除业务断言
变化，指向外层测试预算不足。

项目其余 `runLoop` 集成套件统一使用 30 秒 describe 预算并显式禁止并发。本轮只让该测试组采用
同一约定；生产命令时限、隔离裁决、退出码、凭证与证据断言全部保持不变。

## 可证伪完成合同

| 验收标准                          | 通过证据                                               | 失败观察                          |
| --------------------------------- | ------------------------------------------------------ | --------------------------------- |
| 外层预算严格大于内部 5 秒命令预算 | describe 使用 30 秒，长 canary 用例仍保留独立 60 秒    | 继续使用默认 5 秒，或修改生产时限 |
| 测试间不共享环境竞态              | describe 显式 `concurrent: false`，现有环境清理不变    | 开启并发或删除清理                |
| 业务合同零放宽                    | 两条用例继续断言退出 5、候选保留、无凭证和精确原因码   | 删除、跳过或弱化任一断言          |
| 高负载回归稳定                    | 两条失败用例至少 30 次独立通过，完整文件和全量检查通过 | 只依赖一次重跑绿色                |
| 改动范围独立                      | 只修改本计划和目标测试文件                             | 夹带计时原语、生产代码或发布规则  |

## 实施边界

1. 将目标 describe 改为 `{ timeout: 30_000, concurrent: false }`，与相邻 `runLoop` 集成套件一致。
2. 保留真实 canary 用例已有的 60 秒单例预算；不缩短或扩大其生产行为。
3. 不修改 `strictConfig` 的 `devTimeoutMs`/`valTimeoutMs`，也不更改任何 supervisor 时限。
4. 不新增重试、不跳过 macOS、不按平台分支；同一测试合同继续跨平台执行。

## 黄金原则逐项对照

### 1. 先定义可证伪的完成合同

- **适用性**：适用。上表明确区分测试外层预算、生产内层预算与业务断言。
- **裁决**：30 秒只属于测试协调层；任何生产时限或结果变化都算失败。
- **验证**：目标用例重复、完整测试文件、本地全量与 GitHub 多平台总闸。

### 2. 生成方不得给自己签发通过

- **适用性**：适用。用例必须跑完整 `runLoop` 并由既有机械断言判定，不能只测耗时。
- **裁决**：保留退出码、状态、凭证和证据的全部断言，不用“未超时”代替功能正确。
- **验证**：对比差异并运行原用例，不新增跳过条件。

### 3. 自治范围扩大时同步增加防线与可逆性

- **适用性**：不适用。本轮不扩大 Agent 或发布权限，只校准测试进程允许等待的上限。
- **裁决**：单一测试文件改动可直接撤销；测试继续串行避免共享环境污染。
- **验证**：最终差异只含计划和测试协调配置。

### 4. 原生执行优先，差异只在控制平面

- **适用性**：适用。继续真实执行 Node、Git 和既有受管进程，不替换为伪造结果。
- **裁决**：只在 Vitest 控制层调整预算，生产 Runner 与平台适配零变化。
- **验证**：Linux、macOS、Windows 使用同一测试源码通过。

### 5. 以假绿率和失败恢复衡量价值

- **适用性**：适用。风险是高负载误红，不是假绿；修复不得通过跳过或弱化断言降低误红。
- **裁决**：采用项目既有 30 秒集成预算，并用 30 次独立执行度量稳定性。
- **验证**：失败运行 31927004519、重复结果和多平台总闸共同构成证据。

## 实施顺序

1. 只调整目标 describe 的测试预算与并发声明。
2. 运行两条失败用例、完整测试文件，并至少独立重复 30 次。
3. 运行格式、静态检查、类型检查、全量测试、构建与仓库健康检查。
4. 远端多平台总闸通过后补完成证据并收口计划。

## 完成证据

- 失败事实固定于 Quality Gate 运行 31927004519：macOS Node 22 与 24 的同两条用例均在 5000ms
  外层边界超时，业务断言尚未执行；上一代码提交的两种 macOS 均通过。
- 目标 describe 只增加 30 秒测试预算和串行声明；`strictConfig`、生产 supervisor 时限、退出码、
  凭证与证据断言零改动。
- 两条失败用例独立重复 30/30 次通过；完整 `loop-host-isolation.test.ts` 3/3 通过，真实 canary
  用例继续使用独立 60 秒预算。
- 本地 `npm test` 通过：154 个测试文件、2445 项通过、77 项按预期跳过；格式、静态检查、类型检查、
  构建、仓库健康和依赖审计全部通过。
- 受保护路径由限时政策例外 #244 单独批准；最终 GitHub 多平台总闸仍是合并前硬条件。
