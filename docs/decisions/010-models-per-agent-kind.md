# 010. models 按 agent 工具分段：每个工具定位自己的模型名

## 背景

ADR-006 确立模型路由「透传不映射」，其中一条理由是「一次 run 只有一个 kind，可移植性服务的场景不存在」。2026-07-20 dogfood 备跑实证该理由不完整：`prd.json` 作为配置载体跨运行存活，同一工作区完全可能先后用不同 agent 工具（claude/codex/cursor…）跑引擎，而模型名对工具不可移植——claude 的 `sonnet`/`fable` 传给 codex CLI 就是错名，扁平 `models` 段让「换工具跑」必须改配置文件。

## 决策

`models` 支持两种形状，机械判别（任一键的值是对象 → 按工具分段；否则扁平）：

- **按工具分段（推荐）**：键=工具名（与 `npx coding-x [tool]` 对应），运行时取所用工具的段；缺当前工具的段 → 该次运行路由不启用 + 警告（`src/engine/models.ts` 的 `readModelsConfig(prd, kind)`）。
- **扁平段（兼容旧 PRD）**：对所运行工具原样透传，语义与 0.22.0 及更早一致。
- 两种形状混用 → 整体非法 + 警告（无法判定字段归属哪个工具）。
- story 级 `model` 同样支持字符串或按工具分段；分段时缺当前工具条目**静默**回落阶段链（story 作者只为部分工具标注是合法姿势，区别于顶层缺段的警告）。
- 报告展示不知运行工具，如实列出全部段（`readModelsSections`，每段一行带工具名标注）。

「透传不映射、validator 恒定、升级复用 retryCount」三取舍不变（ADR-006 其余部分继续有效）。

## 理由与备选

- **为什么缺段是警告而不是回落别的段**：把 claude 的模型名传给 codex 是必错配置，不传（用户 CLI 默认模型）比传错名诚实——与 ADR-006「名字写错由 agent CLI 立即报错」同一立场的保守面。
- **为什么工具键不限定枚举**：引擎当前只认 claude/codex，但段键是不透明字符串——未来接入新工具（如 cursor）时旧 prd.json 无需迁移；未知键对当前运行只是「非当前工具的段」，零成本前向兼容。
- **被否备选——tier 抽象（complexity → 各工具模型名映射表）**：ADR-006 已否决过一次；分段方案把映射决策留给配置作者（prd-to-json 派生时与用户确认），引擎仍零模型名单。
- **被否备选——只认扁平段+运行前人工改配置**：现状即如此，dogfood 实证它让多工具工作区的配置管理靠人肉记忆，正是本次用户报告的缺陷。

## 后果

- prd-to-json 派生环节新增确认面：问清用户实际用哪些工具跑引擎，只为确认过的工具生成段（skills/prd-to-json/SKILL.md 已同步）。
- 旧扁平 PRD 零迁移；新分段 PRD 在 0.22.0 及更早引擎上表现为「路由静默不启用」（旧解析器视 builder/validator 为缺失，无警告）——跨版本混跑的观察点，README 已注明推荐形状。
- 面向用户的行为新增（配置形状扩展）随下次发版升 minor（硬约束 5）。
